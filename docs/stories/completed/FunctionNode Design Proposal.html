FunctionNode

A FunctionNode is one model field annotated @FunctionNode whose value is a Portable invocation of a user-defined func or ruleset. The node is drawn with the Boxed Editor's own sheet rules. It shows structure only: the callee, one pin per argument on the left, and one pin per result on the right. Where the values come from is shown by wires. What the values are is shown by output nodes.

The output value on the canvas and the values in the sample model at the end of the page come from the real engine: @edgerules/node 0.0.6-alpha.202607291629. The engine calls named in the menus were run against the same version.

Click the callee chip to pick another callable, the description to edit it, or a result to rename it. Hover an argument for its menu.
Anatomy

Every part comes from an existing Boxed Editor element

Kind tile

Same 40px tile, icon and color as the callee's header row in the Boxed Editor: blue Σ for func, purple for ruleset. The tile is the drag handle.

Tall header, two lines

Line 1: @node-name in bold, the field name in mono, and the node menu ⋮. Line 2: the callee chip and the return type. Same 80px "tall" header as a func row.

Callee chip

The selector for @method. Opens a searchable list of every user-defined function and ruleset in the model, grouped by kind, with the signature on each line. Built-in functions are not offered.

Description row

Optional. Sits under the CALLS line and spans the full width of the argument and result columns. Same yellow tint and italic text as the Boxed Editor's description column, and the same stored text. Click to edit.

Argument band

Neutral grey, like the ARGUMENTS and CONDITIONS bands. Reads ARGUMENT or ARGUMENTS. One 40px row per parameter, showing the name only. Each row has its own ⋮ menu.

Result band

Green, like the ruleset ACTIONS band. Reads RESULT or RESULTS. One row per result field, right-aligned at its pin. No menu. Click a name to rename it.

Pins

Sit on the frame's 1px line, centered on the row. Color is the type, shape is the structure, fill is the connection state. A square pin on header line 2 carries the whole result.

Selection

A 2px primary outline, offset by 1px so it does not cover the frame line. The Delete key removes the node from the flow, not from the model, the same as Remove from flow.

Node menu

The ⋮ in the header acts on the node and its callee

The menu uses the Boxed Editor's RowActionsMenu: Mantine Menu, Tabler icons, labelled groups, and red for destructive items. Items that cannot run are disabled with the reason in a tooltip, never hidden. The second group changes the callee, so it affects every node and field that calls it. The group label says how many callers there are.

Argument and result editing

Arguments have a menu, results are renamed in place

Arguments and results belong to the callee, not to the node, so these edits change the callee's signature or body. The Boxed Editor service already makes these changes safely: setBoxedRowData migrates every call site's @arguments, refuses to remove a parameter the body still uses, and links before it commits. The FunctionNode reuses it.

Sizing

Columns fit their content, in whole steps

  • Two tracksArgument name and result name. Each takes the width of its widest name plus padding, rounded up to the next 40px step, from 2 to 4 steps. Longer names are cut with an ellipsis and shown in full in a tooltip.
  • Header winsWhen the title or the callee chip needs more room than the body, the extra steps are shared between the two tracks. Argument names stay left-aligned at their pins, and result names stay right-aligned at theirs.
  • DescriptionNever widens the node. It takes the full node width and wraps to at most two lines inside its 40px row. The full text is in the tooltip and in the input when editing.
  • Missing sidesA callee with no parameters has no argument column. The node is then only as wide as its header and results.
  • When it changesOn a new callee, or when an argument or result is added or renamed. The node grows to the right, so pins on the left edge stay in place and wires do not jump.
States

One node, eight situations

Choosing the callee

Typing filters functions and rulesets. Arguments with the same name and type keep their bindings when the callee changes. The others become unbound, and their wires are removed.

Argument menu

⋮ appears on the row on hover or keyboard focus, so it costs no width. Here age cannot be deleted because the ruleset's rules test it.

Renaming a result

Clicking level opens an inline input, styled like the Boxed Editor's name input. The note under the node says how many wires will be rewritten.

Unnamed return, argument without a wire

monthly(amount: application.amount * 1.1). The expression is not shown on the node. The dotted pin says the argument is bound without a wire, and the tooltip shows the expression. The unnamed result is in italics because it cannot be renamed.

Record argument, long description

A typed record parameter takes the square pin of a whole record. The description is cut after two lines. The full text is in the tooltip.

Draft and rejected wire

The engine does not evaluate a call with an unbound required argument. It raises a link error (E113), and the whole model stops evaluating. So a node with an unbound required argument is a draft: it is kept only in the editor and not written to the model. Here a wire from income to segment was rejected, and the row shows the engine's message.

New node, no callee yet

A dashed chip is the only call to action. The node writes nothing to the model until a callee is picked.

Editing the description

Opened by Add description or by clicking an existing description. The row stays one step high, and the rows below do not move.

  • Wire colorSame as the source pin, 1.75px bezier. A selected wire gets the primary color.
  • Connect validationset accepts a mistyped or incomplete invocation without an error. On drop, the node therefore writes the invocation, links the model, and reverts the write if linking fails. The message attaches to the row that was wired.
  • Draft nodesA node is written to the model only when every required argument is bound. Until then it lives in editor state, so one half-wired node never stops the rest of the workbook from evaluating.
  • Result typesFor a record result, get(field, 'FIELDS') returns only "@type": "object". The result pins come from the callee schema's @return.
Portable

The node reads and writes one invocation

The left side is what get(field, 'FIELDS') returns and what the node writes back with set, always with named arguments. The right side is the callee schema that defines the rows and pins. Both update when you change the callee on the canvas.
